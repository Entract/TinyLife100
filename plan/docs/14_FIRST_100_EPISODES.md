## Interleaved reading/source encounters for the first 100 episodes

> **These are planned encounter slots, not yet selected source titles.** Source selection happens through the Library policy and must satisfy provenance/rights/prerequisite criteria. The episode numbers remain Life-episode IDs; reading events receive their own IDs and stream positions.

| Insert after Life episode | Reading event | Intended source class | Why it occurs here | Intended effect |
|---:|---|---|---|---|
| 4 | `read_pilot_001` — checking a square/tool guide | short manual / workshop reference | Alex has just discovered that a square is more than a ruler | reinforce reference surfaces and correct use of a simple tool; first tiny explicit reading |
| 14 | `read_pilot_002` — measurement and experimental evidence | school text / short textbook section | Dr. Imani has challenged Alex's plausible-but-untested friction story | formalize observation, variable, repeat measurement, and evidence after the need is felt |
| 30 | `read_pilot_003` — ordinary nontechnical reading | short literature/essay, rights-clear | deliberate break after a project postmortem | establish that Alex reads for ordinary human reasons; add human-authored style without compulsory technical reflection |
| 38 | `read_pilot_004` — introductory circuit explanation | beginner electronics text | Alex now has physical measurements of resistors/voltage and is ready for formalization | support the move from concrete circuit behavior to Ohm's law without making Alex's prose carry all exposition |
| 49 | `read_pilot_005` — motor electrical characteristics | motor datasheet | the motor behaves differently under load than Alex expected | teach that ratings have conditions; introduce stall/startup current from an authentic technical artifact |
| 60 | `read_pilot_006` — calibration/reference measurement | technical handbook / lab guide | two thermometers disagree and Alex has created a first calibration relation | deepen reference quality, calibration, residual error, and uncertainty |
| 62 | `read_pilot_007` — microcontroller getting-started material | official documentation / manual | Alex has a real board and wants sensor readings in software | source-driven procedural learning; first longer documentation encounter |
| 79 | `read_pilot_008` — reproducing bugs / version-control basics | software documentation / concise technical text | Leila insists on a minimal repeatable failure and code is changing too quickly | introduce documentation as working knowledge rather than a tutorial dump |
| 94 | `read_pilot_009` — hysteresis and threshold control | control/electronics text | Alex has already invented the practical two-threshold solution | formal term arrives *after* lived mechanism; compare source explanation with existing intuition |
| 100 | `read_pilot_010` — first look at feedback control | accessible control text, selected section only | Alex ends the first hundred episodes asking how to control continuously varying temperature | seed the next arc without resolving it immediately; some ideas should remain only partly understood |

### Design notes

1. **Do not select ten sources merely to fill these slots.** A reading may be removed if the best Life design does not need it.
2. At least one source should be reread later rather than treating all readings as disposable.
3. At least one reading should create confusion or a wrong generalization that is corrected by experiment.
4. `read_pilot_003` should not be turned into an engineering analogy immediately. It exists partly to protect the Life from becoming an educational theme park.
5. The datasheet/manual events should preserve authentic document structure where rights/policy permit inclusion.
6. The first pilot should use a small, inspectable source set; source diversity becomes more important as the corpus scales.
